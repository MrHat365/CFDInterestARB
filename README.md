# CFDInterestARB

CFDInterestARB 是连接 MetaTrader 5 的 Windows 桌面工具，用于查看隔夜利息、发现外汇组合机会、观察合成价差，以及按人工设定的条件执行多配对交易。

策略围绕组合的净隔夜利息展开，同时控制入场价差、往返交易成本和退出收益。用户决定交易方向、每层手数、最大目标持仓和执行条件，程序负责监测条件并执行受管开平仓。自动入场与自动出场分别启用，保存任务不会立即下单。

## 功能与适用范围

| 功能 | 用途 |
| --- | --- |
| 多账户管理 | 绑定本机 MT5 终端，查看连接状态，打开各账户控制台 |
| 隔夜利息与规则 | 查看品种交易规格、买卖方向隔夜利息及变化记录 |
| 组合机会 | 按隔夜利息生成外汇闭环组合，查看交易腿与方向 |
| 价差图表 | 展示历史及实时合成价差、统计参考线和纸面信号 |
| 手动交易 | 按当前组合提交一层，核验账本并平掉归属明确的策略仓位 |
| 后台自动交易 | 多个配对独立设置入场、出场条件，分批达到目标层数 |
| 本地保存 | 保存账户配置、任务条件、订单意图、成交回执与持仓归属 |

**受管实盘交易目前限于 MT5 对冲账户中的 FOREX / FOREX_NO_LEVERAGE 计算模式品种。** 不支持净持仓账户，也不表示支持所有名称中带有 CFD 的金属、指数、能源等合约。组合每个任务包含 2～5 个不同品种，每账户最多保存 32 个任务。

入场改善依靠等待设定的价差与成本条件，触发后提交市场执行请求；不提供自动寻找全局最优价格或保证成交价格的功能。多腿订单依次执行，不能保证同时成交。正隔夜利息和对冲关系也不代表必然盈利，实际结果还取决于价差变化、点差、费用、滑点和持有时间。

## 安装与启动

### 环境要求

- Windows，建议使用 64 位 Python 3.12。
- 已安装的 MT5 终端，且已手动登录目标账户。
- 允许 Python 接口交易的终端设置及账户权限；实际成交还须符合经纪商规则。
- 正常的网络连接、系统时间和可写的本地项目目录。

macOS 无法原生运行本项目所需的 MT5 交易接口。以下安装与启动命令均用于 Windows。

### 源码启动

下载并解压仓库，或通过 Git 获取源码。进入项目根目录，在 PowerShell 中执行：

```powershell
python -m venv .venv
.\.venv\Scripts\python -m pip install -r requirements.txt
.\.venv\Scripts\python app.py
```

以后启动只需执行最后一行。源码运行只需要安装 `requirements.txt` 中的运行依赖。

## 首次使用

1. **登录终端。** 打开目标 `terminal64.exe`，在 MT5 中登录，并确认行情正常更新。
2. **添加账户。** 在账户管理页点击“扫描 MT5 客户端”，再点击“添加账户”；也可以在账户对话框中通过“浏览…”直接选择终端。
3. **绑定身份。** 填写与终端一致的账户登录号、服务器名称，并选择对应终端路径。工具连接已有终端，不代替用户登录或切换 MT5 账户。
4. **连接控制台。** 点击账户行的“控制台”，等待连接就绪。多个账户应分别绑定不同终端，不能让两个活跃账户共享同一个终端进程。
5. **读取规则与利息。** 在“规则 · 隔夜利息”页点击“加载全部交易规则”，按需要设置刷新间隔或过滤品种。
6. **选择组合。** 在“交易机会”页设置最大腿数，点击“由隔夜利息生成交易机会”。双击一行，将组合载入“策略控制台”，等待订阅行情及历史价差加载。
7. **选择执行方式。** 纸面观察留在“策略控制台”；条件自动实盘执行进入“后台自动交易”。两页的执行开关相互独立。

账户编辑页不收集新密码。旧配置中存在密码时，可勾选删除已保存的旧密码。已有账户的登录号、服务器不可直接修改；更换终端绑定前先断开会话。

### 报价时间设置

| 设置 | 含义与建议 |
| --- | --- |
| 报价时间基准 | 默认 `UTC`。只有确认经纪商 API 的 tick 和历史时间存在同一非标准偏移后，才改为固定偏移（如 `UTC+03:00`）或相应 IANA 时区 |
| 市场报价最大年龄 | 默认 60 秒，可设 5～120 秒；超过该时龄的市场报价不可作为自动交易的有效输入 |

MT5 图表显示的服务器时间不代表接口时间需要转换。不要通过修改时区让过期行情看起来更新。自动任务还单独检查本轮各腿行情的读取时效，要求在 1 秒范围内；读取及时不等于市场报价本身新鲜。

## 如何理解价差、成本和隔夜利息

### 价差不是账户利润

价差表示目标腿报价与其他腿合成报价之间的偏离。常见方向示例为卖出 USDJPY、买入 USDCHF 和 CHFJPY：

```text
合成买价 = USDCHF Ask × CHFJPY Ask
价差 = USDJPY Bid − 合成买价
```

价差使用目标腿报价单位，不是账户货币金额，也不是 Z-score。不同组合、方向的阈值不能直接通用。每个自动任务的买卖方向固定，不会因为价差符号改变而自动反向交易。

交易手数控制资金规模和币种敞口，不作为合成价公式的指数。修改各腿手数后，应重新核对组合方向、目标腿、残余敞口及金额估值。

### 自动任务的金额口径

后台任务表中的成本、净息、净盈亏，以及任务编辑器内的金额阈值，均以该账户的币种计价。

| 指标 | 计算与用途 |
| --- | --- |
| 每层往返成本估计 | 按当前各腿买卖报价估算立即开仓再平仓的点差损失，加上双边佣金、其他费用和滑点预留 |
| 普通单次净息 | 按固定方向、每腿实际手数、当前 swap 规则及汇率汇总，用于判断组合是否达到正息要求 |
| 持仓净盈亏估计 | 汇总任务持仓按当前报价平仓的估值、持仓 swap、可取得的历史成交收益和费用，再扣除预计退出费用及滑点 |

费用预留按“每手每侧”填写；单层往返预留为 `2 × 各腿手数之和 ×（费用预留 + 滑点预留）`。费用填 0 表示已确认该项为 0，不代表未知。成本上限填 0 也不是禁用成本检查，而是只允许估算成本不大于 0 的入场。

普通单次净息不包含三倍息、节假日或未来费率变化。独立账户级融资扣费、通过重开仓记息等特殊机制不在当前自动收益估值范围内。保存任务前须核实经纪商的费用和标准 position/deal swap 记账口径。

例如，单层预计成本为 6、普通单次净息为 2，仅从这两个数看，需要约 3 次普通计息才能覆盖初始估算成本；实际平仓仍受价差变化及费用影响。这个比值只是理解成本的例子，不是程序承诺的回本时间。

## 图表与纸面观察

“策略控制台”默认勾选纸面模式。载入组合及历史后，点击“开始监测”，观察价差、参考线与信号。Z 窗口以分钟计，统计使用已收盘 M1 数据并结合 H1 先验；入场阈值、网格步进和层数用于图表策略观察。

- 缩放或平移图表可查看历史，点击“跟随最新”恢复跟随实时数据。
- 时间轴和十字光标使用 UTC。
- “重新加载历史价差”重新请求当前组合的历史数据。
- 历史价差按各腿历史 Bid 收盘价并以当前点差近似 Ask，不是当时真实可成交的完整盘口。
- 历史覆盖长度取决于 MT5 实际可用数据，不能据此保证回测成交结果。

纸面信号不是真实成交。取消纸面模式允许手动受管开平仓，但图表 Z-score 网格本身不会自动提交实盘订单。要自动执行，请配置“后台自动交易”任务。

## 手动开平仓

1. 载入组合并确认各腿行情有效。
2. 设置“最重腿手数/层”、最大层数、账户总手数上限和保证金使用率上限。
3. 点击“核验策略账本”，核对真实受管持仓及是否存在未确认委托。
4. 取消纸面模式；“手动进场”为两步确认按钮，首次点击后须在 3 秒内再次确认才发出操作。
5. 根据执行回执和持仓表确认结果，不以信号列表中的记录判断成交。
6. 需要退出时使用“平策略持仓…”，选择待平的策略方向并确认。可以处理重启前留下的、归属能够核验的策略持仓。

手动进场不使用后台任务的价差、成本和净息门槛，操作前需自行判断入场条件。工具仅平掉能够核验归属的策略仓位，不自动接管人工仓位。手动关闭或修改受管仓位后，应重新核验账本。

## 配置后台自动交易

### 创建与启用

1. 在“策略控制台”载入所需组合。
2. 打开“后台自动交易”，点击“从当前组合新建”。
3. 核对每个品种的固定买卖方向，填写每层实际手数及下表中的条件。
4. 确认费用和 swap 记账口径，点击保存。**保存后入场、出场均暂停。**
5. 选中任务，通过“启停入场”和“启停出场”分别打开所需执行开关，并等待后台回执确认。
6. 查看任务表中的持仓/目标层、价差、成本估计、净息、净盈亏及状态原因。

可重复以上步骤创建多个组合任务。同一账户同一组品种和买卖方向不能重复创建任务；应编辑已有任务。多个任务轮转检查，出场优先；同一账户每次执行一个篮子，不能理解为所有配对、所有腿同时成交。

### 入场参数

| 参数 | 含义 |
| --- | --- |
| 每层实际手数 | 每条腿一次完整入场的手数，须满足品种最小值、最大值及步长 |
| 最大目标持仓（层） | 允许持有的受管批次数，范围 1～100；不是总手数或信号条数 |
| 入场价差条件 / 门槛 | 选择 `≥` 或 `≤`，并填写对应报价单位的阈值 |
| 每加一层要求价差再改善 | 随当前持有层数提高后续入场要求；`≥` 时门槛增加，`≤` 时门槛降低 |
| 最短分批间隔 | 两次分批执行之间的最短等待时间，至少 0.2 秒；不是成交延迟承诺 |
| 入场等待上限 | 从启用入场开始计算等待期限，0 表示不限；到期停止继续入场，不会平掉已有持仓 |
| 每层往返成本上限 | 当前成本估计不得超过此金额；0 为严格的零成本上限 |
| 每手每侧佣金及其他费用预留 | 每腿每手每个交易方向的预计费用，须按账户币种填写 |
| 每手每侧滑点预留 | 用于估值的滑点金额预留，不是经纪商保证的最大成交滑点 |
| 每层最低普通单次净息 | 当前净息必须达到此门槛且严格为正；填 0 仍不允许零息或负息入场 |
| 全账户总手数上限 | 包含其他持仓的账户总手数限制，必须大于 0 |
| 全账户保证金使用率上限 | 取值大于 0 且不超过 1，例如 0.3 表示 30% |

入场需要同时满足价差、成本、净息、仓位目标及账户交易检查。相关活跃任务或仍有持仓任务的账户限额取较严格值，共享账户额度不会按任务重复分配。

例如，入场条件设为 `价差 ≥ 0.020`、改善步长为 `0.005`，则持有 0、1、2 层时，下次入场门槛分别为 `0.020`、`0.025`、`0.030`。这些数值仅用于说明，不能直接套用到其他品种。

达到目标持仓后，自动入场开关会停止。程序不会为了凑够目标层数而忽略成本条件，也不会持续自动补回已经退出的层数。

### 出场参数

| 参数 | 含义 |
| --- | --- |
| 每层出场净利润门槛 | 对每一层单独判断净收益估值，不是整个任务合计利润 |
| 盈利退出还须满足价差条件 | 勾选后，盈利退出必须同时达到出场价差条件；不勾选则只检查净利润门槛 |
| 出场价差条件 / 门槛 | 选用 `≥` 或 `≤` 判断当前价差，仅在上项启用时约束盈利退出 |
| 每层亏损退出限额 | 大于 0 时启用；净收益估值达到相应负值时触发退出，0 表示禁用 |
| 每层最长持有秒数 | 大于 0 时启用，到时允许亏损退出；0 表示禁用 |

**所有自动出场条件都依赖“出场”开关开启。** 仅开启入场不会自动执行止盈、亏损退出或到时退出。亏损和持有时间条件不要求先达到盈利门槛；这些是触发条件，不保证最终成交亏损不超限。

一旦任务进入自动退出周期，程序会关闭该任务的入场开关，避免边退边加。仍有退出周期仓位时，不能重新启用入场；处理完仓位后，再由用户决定是否开始新一轮。

任务表中的“持仓净盈亏估计”是各层合计，不能直接与“每层出场净利润门槛”比较。一个任务合计盈利，并不表示每一层都已满足退出条件。

### 暂停、修改与删除

| 操作 | 效果 |
| --- | --- |
| 暂停入场 | 停止后续自动加仓，不关闭已有仓位；已启用的出场继续按条件判断 |
| 暂停出场 | 停止自动止盈、亏损退出和时间退出，不关闭已有仓位 |
| 全部暂停 | 暂停当前账户所有任务的入场及出场，不是平仓操作 |
| 立即平选中任务 | 确认后尝试平掉该任务归属明确的全部仓位，不要求盈利，并暂停任务；须核对执行回执和剩余仓位 |
| 编辑选中任务 | 先暂停两个开关；已有持仓时不能更改交易腿或每层手数，目标层数不得低于现有层数 |
| 删除 | 两个开关均暂停且没有该任务持仓后才允许删除 |

停止请求以后台确认回执为准，不能撤销已经发送给经纪商的交易请求。回执超时时先刷新及核对 MT5，不要把超时当作没有成交。

## 后台运行与断线恢复

后台任务由账户连接管理，不依赖某个图表是否显示。

| 操作或状态 | 对后台任务的影响 |
| --- | --- |
| 切换组合、切换标签、关闭账户控制台 | 自动任务继续运行，只要主程序和账户连接仍正常 |
| 图表纸面开关、按 Escape 停止图表监测 | 不控制后台实盘任务 |
| 断开账户或退出主程序 | 停止后台执行，已有经纪商持仓不会因此自动平掉 |
| 断线、执行异常、持仓归属无法核清 | 自动任务暂停；恢复后须人工核对并分别重新启用入场、出场 |
| 重启程序 | 恢复配置和账本，不自动恢复交易开关 |
| 电脑休眠、关机、MT5 退出 | 无法继续监测和交易 |

这是随桌面主程序运行的后台任务，不是独立 Windows 服务。长时间运行时应保持主程序、对应 MT5 终端和网络可用，并关闭会中断运行的系统休眠设置。

账户存在任何挂单时，包括其他品种的人工挂单，新增仓位会被阻止。应核对并自行处理挂单，程序不会自动撤销人工挂单。

未知委托结果、部分成交或账本异常可能阻止继续执行。先查看 MT5 的持仓、订单及成交记录，再使用“核验策略账本”或刷新任务状态。历史证据不足时会保持阻断，不凭“查不到成交”自动重发。

## 数据保存与备份

源码运行时，数据保存在项目目录下的 `mt5_trader/mt5_trader.db`。其中包含账户与终端绑定、隔夜利息记录、任务条件、受管订单与持仓归属等数据。应用会使用 SQLite 的 WAL 辅助文件。

- 更新代码前，正常退出应用并等待后台进程结束，再备份完整数据库。
- 如果仍存在 `mt5_trader.db-wal`、`mt5_trader.db-shm`，应在所有相关进程停止后与数据库一起保留，不能单独删除未合并的 WAL 文件。
- 迁移到另一目录或电脑时，保留完整数据库及其必要辅助文件，并重新核对终端绑定路径；只迁移账户信息会丢失策略归属和恢复依据。
- 不要让同一账户同时由多个数据库副本或多个程序实例执行交易。
- 数据库、日志和本地文档不应作为源码上传。仓库保留本 README 作为产品说明和使用入口。

## 常见问题

| 现象 | 检查与处理 |
| --- | --- |
| 账户无法连接 | 确认 MT5 已打开并登录，绑定的终端路径存在，登录号和服务器完全一致，终端没有被另一个活跃账户占用 |
| 失败后无法重连 | 先断开会话，在账户页选择“清理失败 worker”；核对 MT5 在途委托后再连接 |
| 没有交易机会 | 先加载规则和隔夜利息，检查品种覆盖、组合腿数和支持的利息计算方式；正息机会并非始终存在 |
| 图表为空或开始监测不可用 | 等待组合各腿订阅和历史加载，检查终端历史数据，必要时点击“重新加载历史价差” |
| 保存任务失败 | 检查手数步长、账户总手数和保证金上限、费用确认、重复方向或任务数量；以弹窗原因处理 |
| 已启用入场但没有下单 | 查看状态列；可能尚未达到价差、成本或净息条件，达到持仓目标、等待期限到期，或账户存在挂单和未核清仓位 |
| 盈利但没有自动平仓 | 确认出场开关开启；检查每层净利润、可选出场价差条件，以及收益所需成交历史是否完整 |
| 报价过期或跨腿读取超时 | 检查市场是否开市、网络和系统时间；不要通过随意改时区绕过报价时龄限制 |
| 净息或净盈亏显示不可用 | 检查品种 swap 模式、账户币种汇率、成交历史和持仓归属；未知数据不会自动按 0 处理 |
| 断线恢复后任务没有继续 | 核验账户和账本，再人工分别启用入场、出场，这是预期行为 |
| 关闭窗口后仍有交易 | 关闭账户控制台不会停止后台任务；使用任务开关或“全部暂停”，并确认后台回执 |

## 使用边界

- 自动交易需使用支持的账户模式、品种规格、成交方式和记息口径；不适用的组合会被拒绝。
- 图表、成本和收益显示用于条件判断，真实成交以 MT5 和经纪商记录为准。
- 手数、保证金限制及币种残余检查不是全账户最大亏损或最大回撤保证。
- 历史图表不构成完整回测；默认参数不代表适合特定账户，正式使用前应在目标 Windows 与经纪商模拟账户环境确认实际行为。
