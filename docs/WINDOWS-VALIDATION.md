## 2. 会话全生命周期

- 正常连接：启动已登录的绑定终端、核对login+server，再打开控制台。账户列表/控制台一致；等待数据和订阅确认后才显示新鲜报价。
- 重复连接：连续点击/反复打开同账户，系统只出现一个worker；不同账户不同终端可并发。
- 主动断开：记录PID、线程和handlers，确认stop到达worker，在途事务结束，进程退出，重连恢复订阅。
- 关闭再打开控制台：连接保持，状态立即恢复；Qt/Toast/图表不累积孤立定时器或订阅；监测不自动继续。
- 登录等待/初始化超时：终端未登录、错误账号、缺失路径、无MT5依赖均应明确反馈；stop/ping不被登录等待阻塞。
- 网络断开和恢复：模拟终端无连接，观察reconnecting；恢复后身份仍匹配，订阅恢复，旧腿缓存不参与计算。
- 重连失败再恢复：保持断网数个周期后恢复；不能生成第二个worker。
- 旧事件：向新视图投递旧generation状态/tick/history，确认全被拒绝；旧status revision不能覆盖较新快照。
- 同login不同server：更换终端账户或服务器，在发单前必须拒绝；不得误报已连接。
- 行情停滞：API正常但broker时间不变，显示真实年龄并暂停监测；没有收到新报价不能靠poll重复包保持数据可用。
- 应用重启：恢复账户绑定但不恢复已连接/交易意图；检查执行日志，不自动补发结果不明的委托。
- 退出：多会话、历史请求、swap扫描与订单分别进行时退出，核对worker和线程不遗留；强杀路径要有明确风险记录。
