# 隔夜利息策略：入场成本、可兑现收益与退出策略专项审查

日期：2026-10-15。对象：当前工作区源码，包含此前两轮尚未提交的修复。

本轮交付是代码问题识别和详细修复方案，**没有实施下述交易逻辑变更**。遵照用户要求，没有运行应用、worker、MT5、测试、构建或安装依赖，没有访问真实交易数据库及账户。以下行号对应本报告生成时的源码。

## 1. 结论与业务目标

当前程序是“隔夜利息排序 + 价差 Z-score 网格入场 + 回均值退出”。此前增加的受管执行解决了订单意图、持仓归属和异常阻断的一部分问题，但没有建立“按实际成交规模核算全部成本、按计息日历预测回本、按可兑现净利润退出”的经济决策闭环。

降低成本、在有利价差入场可以缩短回本所需时间；对冲本身并不消除点差、佣金、残余敞口、基差变化和利率变化。不能把价差回归作为确定发生的收益，也不能把当前正息无限外推。适合本项目的目标是：在限定持仓时间和损失预算内，筛选保守净收益达标的组合；不达标则不新增仓位，已有仓位独立管理风险。

优先级 P1 表示会改变交易方向、盈亏判断或使持仓风险无人管理；P2 表示收益排序、数据或支持范围存在偏差。这里的严重程度针对用户的隔夜利息策略，不是断言已发生实盘亏损。

## 2. 源码问题与逐项修复

### E01 / P1：正息组合会被信号直接翻成另一个经济方向

证据：`strategy.py:198` 对高 Z 发出 `sell`；`ui/console.py:1935` 将 `sell` 映射为所有腿反向，同时在 1942 行原样保留旧 `swap`。`managed_trading.py:314` 的预检查不检查隔夜利息。

影响：选择“买 A、卖 B”的正息组合后，自动信号可能实际交易“卖 A、买 B”。反向的 swap 必须重新逐腿取 long/short，可能两个方向都付息。旧 swap 元数据虽然没有被执行器用于扣款计算，但会保留错误的经济描述，而且不存在阻止负息反向开仓的条件。

补充：`opportunities.py:245` 和 249 行已经分别调用 `_build` 正确重算两个方向；问题发生在后续执行映射。该文件 152–155 行“净息恰好互为相反数”的说明也错误，不能据此再把反向收益实现为简单取负。

修复：固定一个明确的 `orientation_id` 表示整篮子的买卖方向；信号只请求“评估这个方向的入场”，不能自行翻转。反向必须作为独立候选，重新计算实际手数、买卖报价、佣金、swap 和压力情景。纯收息模式下，保守净 carry 不合格的方向不进入自动交易；若未来支持负 carry 的价差交易，应是另一个明确的策略模式和预算。

验收：原方向 +2、反向 -5 的假设净息条件下，高 Z 不得绕过收息筛选开出反向组合；多空 swap 均为负也不能生成“取负变正”的结果。

### E02 / P1：价差统计方向与组合盈亏方向不一致

证据：`strategy.py:278` 的价差为目标卖腿 Bid 减其余腿合成价；`strategy.py:207` 在低 Z 买、高 Z 卖；`ui/console.py:1935` 的 buy 保留原腿、sell 翻转。

具体反例：原组合为卖 USDJPY、买 USDCHF、买 CHFJPY。设 c=USDJPY、a=USDCHF、b=CHFJPY，忽略点差变化、费用和汇率换算影响，只分析方向，D=c−ab。卖 USDJPY 的基础货币数量为 Q，买 USDCHF 为 Q，买 CHFJPY 为 Qa，则在局部配平点：

```text
dΠ（JPY）≈ −Q·dc + Q·b·da + Q·a·db = −Q·dD
```

固定 a、b 时这是直接的卖出腿盈亏关系：c 从 150.10 降到 150.00，原卖出腿获利；翻成买入则亏损。因此 D 偏高后向下回归，对应原方向获利，而现有高 Z 信号会翻转。D 偏低时保留原方向，也不符合“买低价差等待上升”的解释。

这证明当前三角组合映射存在具体反例，不代表所有合约都能用同一个负号修复。非线性合成、目标腿选择、取整后的实际持仓都会改变敏感度。正向和反向 executable spread 也不只是取负，因为买卖侧不同。

修复：保留定价偏离图作为观测量，但用每腿合约盈亏函数计算实际组合的场景收益。为每种方向建立价格扰动与现金盈亏映射；明确“偏离增大/缩小谁获利”。以期望平仓报价与实际入场报价计算账户币种收益，不能用原始跨货币价格差直接当利润。不要只全局交换 buy/sell。

验收：只移动目标腿、只移动任一合成腿、三腿一致移动、反向及倒数报价等场景都能把方向和每腿盈亏对上；交易量取整之后重新验证。

### E03 / P1：没有整篮子往返成本和回本时间准入条件

证据：`managed_trading.py:314` 检查权限、手数、保证金、IOC 和币种残余；没有 commission、fee、预计退出成本、持有期或最小净收益判断。`ui/console.py:1962` 请求只携带归属、腿和仓位上限。

影响：正确使用 Ask 买入、Bid 卖出，只保证选对报价侧，并不保证收益覆盖交易成本。多腿甚至五腿组合可以有最高净息，但因宽点差和双边佣金需要很久回本；原网格还可能在不利成本下继续加层。

修复：新增统一经济估值，先生成实际可交易手数，再计算保守持有情景净收益、初始可兑现亏损、回本结算时刻、压力损失和保证金占用。设置 `max_entry_drag`、`max_payback_time`、`min_scenario_net_profit`、`max_stress_loss`。手续费未知时不新增仓，不能默认零；人工开仓按钮也走相同经济校验。Z-score 仅用于择时，不能绕过经济门槛。

验收：相同 Z、相同净息但点差/佣金不同的两组订单，应产生不同准入结果；手续费未知必须显示明确拒绝原因。

### E04 / P1：出场只看回均值，不看可兑现净利润和持仓时间

证据：`strategy.py:190` 在 `abs(z)<=0.3` 时发平仓；`managed_trading.py:447` 关闭相同策略与方向的全部批次。批次虽然在 420 行记录创建时间，决策中并未使用持有时间。

影响：价差回均值可能不足以覆盖多腿成本；净盈利已达标也可能因 Z 未到阈值而不退出。同方向各层的入场价和已收利息不同，不能由一个全局 Z 推断全部层的盈亏。滚动均值跟随新价位，还可能在价格没有有利回归时发出退出信号。

修复：按 batch 估值。收益退出条件使用“已实现现金流 + 当前可执行平仓盈亏 − 剩余平仓费和额外滑点准备金”。可以按明确的组合整体利润目标退出，但必须展示各层贡献和汇总成本。增加 `batch_ids`、`exit_reason`、利润退出有效期和收益底线；风险退出允许亏损，不能被“净利润必须为正”阻挡。手动退出也不应被盈利门槛锁死。

持有决策比较从现在继续持有的增量收益与增量风险；已付成本用于生命周期盈亏对账，但不能成为永远等回本的理由。最大亏损、最大持有期、负 carry、保证金风险等都有独立处理策略。

验收：Z 已回归但净亏损时不标记盈利止盈；Z 未回归但净利润达标时允许收益退出；期限/损失越界时允许亏损风险退出；各层可独立估值和选择。

### E05 / P1：账本能证明持仓归属，但不能证明赚了多少钱

证据：`managed_trading.py:150` 对账重点是成交身份、成交量和剩余仓位；210 行持仓快照只保留标识、方向、手数；406 行只保存 retcode/order/deal/volume/price。UI 有账户成交手续费展示，但没有用于策略决策的完整收益账本。

修复：以账户身份和 deal ticket 为幂等键保存实际 price、volume、profit、commission、swap、fee、时间、订单和 position_id。保存 batch 与成交归属；每次部分平仓也更新已实现现金流、剩余成本和剩余持仓。费用最低收费、分段费率、入场预收往返佣金等按 broker 规则建模。

注意：部分 broker 把融资费用体现在 position.swap，部分在平仓 deal，部分以独立资金流水收取，某些模式会重开仓调价。不能把累计 position.swap 和已结算 deal.swap 重复相加。无法直接归属的账户级费用进入待分配账目，展示误差，不得凭空精确分摊。估值应有 `known/estimated/unavailable` 状态及对账差额。

验收：重复读取历史不重复计费；重启前后总收益一致；部分平仓不丢费用；已预收往返佣金不再重复扣；终端结单与组合账本可以逐笔核对。

### E06 / P1：利息更新没有驱动当前策略和持仓重估，也没有结算日历

证据：`ui/console.py:1250` 更新行情数据表，已有组合保留在 1501 行设置的 `_current_legs` 中；`worker.py:647` 的变更指纹仅含 long、short 和三倍息日；`database.py:41` 快照未保存 swap_mode、换算基准和合约规格。

当前不能把采集到的“USD/天”直接视为持仓每满 24 小时就收到的钱。必须考虑每腿结算时点、资格、每周倍率、节假日和交易商时区；不同腿的三倍息日可能不一致，某个结算日的净息可能与普通日相反。规格和换算率变化也会改变货币价值，即便原始 swap 数值未变。

修复：版本化保存原始 swap、mode、单位、合约大小、转换率及来源时间；持续刷新当前方向和已持仓规模的估值。引入 broker 结算日历，区分“正常单次结算参考净息”“下一次实际结算估计”“已经到账利息”。设置新鲜度和规则有效期，超过后不新增仓位；已有持仓进入风险重估。正息腿下调、负息腿加重应逐腿压力处理，不能仅给净额打折。

验收：未跨结算时点收益为零；三倍息、周末/节假日、不同腿不同倍率、DST、swap 转负、只变 mode/contract/tick value 都更新结果。

### E07 / P2：展示和排序用归一化净息，与实际规模和资金效率脱节

证据：`weights.py:113` 将最大权重归一到 1；`opportunities.py:201` 用归一权重算净息、217 行提前取两位小数、253 行仅按净息排序截断前 100；`spreads.py:217` 才按每层手数缩放并取整；`ui/console.py:1508` 直接显示机会净息为 USD/天。

影响：最大腿为 1 手的参考收益不能当作实际 0.01 手层的收益；在取整前约差 100 倍，取整后还可能改变比例。生成器没有纯收息模式的正净息筛选，负息候选也会保留。仅按净息截断还可能在成本评估之前丢掉小净息、低成本、更快回本的组合。

修复：内部保持完整精度，只在显示时四舍五入。分别展示参考组合和实际订单/实际持仓净息。先按支持范围、经济可行性和风险过滤，再用回本时间、保守净收益/保证金、残余风险比较；粗筛可保留多个指标的候选集合，再成本精筛，不固定用净息前 100 代替全流程。

验收：改变每层手数立即重算成本、净息、回本时间和风险；取整成不可对冲规模时拒绝；全为负息时收息模式显示没有合格机会。

### E08 / P1：信号有效价差未贯穿到真实成交

证据：`ui/console.py:1962` 请求没有价格边界、报价快照版本或失效时间；`managed_trading.py:417` 按手数从大到小市价执行；`worker.py:1116` 和 1153 行统一默认 deviation=20 points；部分成交后主要检查数量和残余。

影响：行情“仍然新鲜”不等于“仍然有足够的净收益”；队列等待或逐腿成交期间，点差可能扩大。20 points 对不同合约的现金成本不同，且不能跨执行模式把它视作绝对成交价保证。手数最大也不代表美元风险最大或最难对冲。

修复：请求带 `quote_snapshot_id`、`valuation_version`、`valid_until`、账户币种成本预算和逐腿报价边界；worker 发送第一腿前重新抓取整篮子同步报价并重新估值。按流动性、现金敞口和失败后对冲难度选择执行顺序。每次实际成交后以真实成交价重算剩余执行方案，设置最大未对冲敞口和最长未对冲时间。

第一腿未成交时，经济条件失效直接取消新入场；已有成交时，不能因利润不足就简单停止剩余腿。应按预先配置的损失预算比较补齐对冲或撤回已成交仓位，避免无限追价。未知成交结果继续遵循既有“先查证、禁止盲目重发”，补救动作也必须持久化和幂等。

验收：排队后机会消失不发第一腿；首腿滑点过大、主动腿部分成交、后续腿拒绝时有有界风险处置；补救不会重复下单。

### E09 / P1：5% 残余容差和总手数限额不是适合收息的经济风险限额

证据：`managed_trading.py:369` 接受相对最大单腿币种流 5% 的残余；`weights.py:47` 用参考 FX rates 解权重；手数取整后重新检查比例，但没有与可赚利息比较的账户币种压力损失限制。

影响：名义本金的很小百分比，也可能大于多次隔夜利息。不同合约的 1 手不可直接比较；中性估计也受合约规格、实际成交价格和转换率影响。

修复：保留逐币种数量检查，并增加绝对账户币种敞口、每腿风险敏感度、价格/汇率压力损失和全账户同币种集中度预算。使用整数步长约束生成可执行手数，再评估净息、成本和残余；无可行规模则不交易。不得为满足 minimum lot 静默放大一腿。分层加仓必须按新增成本、整篮子风险和已有持仓组合再评估，不因进入下一网格自动获得额度。

验收：比例在 5% 以内但压力损失超预算仍拒绝；多个组合相同风险方向累计超限仍拒绝；小手数取整破坏中性时解释原因。

### E10 / P1：统计时间尺度骤变，历史也不是真实可成交价差

证据：`strategy.py:61` 用 H1 全历史先验；`strategy.py:340` 在 10 个 live 点后切换到实时滚动窗口；`strategy.py:109` 的均值方差包含当前值。`worker.py:895` 从位置 0 读取 OHLC，包括未完成 bar；916–951 行把当前 `_spread_adj` 加到历史买腿价格，未保留当时逐笔 bid/ask。

影响：10 个实时采样点与几千根 H1 的统计意义完全不同；阈值可在暖机时突变。价格在不利新水平横盘后，均值会追上价格，Z 回零不说明投资已获利。同一 bar 的时间标签也不能保证各腿最后成交/报价同时发生。当前历史曲线不能证明低成本入场曾经可执行。

修复：图表保留现有历史但标注近似；决策使用固定时间尺度的已完成采样段、明确暖机长度和滞后统计。分别记录 mid 定价偏离、当时入场可执行边际和可兑现 P&L，不让点差扩大被当作有利错价。采集逐腿时间戳、bid/ask、规格和 swap 版本，限制跨腿时间差。历史无双边报价时只能做价格行为观察，不能输出可成交收益回测。

验收：历史→实时切换不改变样本频率；只扩大点差不创造更优的可兑现机会；基差永久移位时不能只因均值追上价格就标记盈利；未完成 bar 不进入已完成统计。

### E11 / P1：持仓管理随控制台监测一起停止

证据：`ui/console.py:1144` 关闭窗口时停止监测；1720 行停止信号；1808 行由 UI 将信号转换为开平仓。worker 受管路径处理请求和对账，没有独立周期性的经济退出决策。

影响：停止新增交易、切换展示的组合或关闭窗口时，仍有仓位可能需要净息恶化处理、限时退出和保证金保护。

修复：把已登记持仓的估值和风险政策放到应用/账户 worker 生命周期中，与 UI 的开始入场按钮分离。UI 关闭停止新增入场，不取消已登记持仓策略。用户配置的持仓政策需持久化，恢复后先对账再管理；进程完全退出或终端断线时应明确为无法执行风险管理，不能显示“受保护”。不要偷偷把“停止所有自动执行”的显式用户意图解释为继续发单，需提供区分清楚的控制状态。

验收：仅关闭控制台、切换组合或停止新增入场时，持仓估值/预先授权风险政策仍有效；重启后先对账，旧信号不自动重放。

### E12 / P2：产品范围与“CFD 套息”表述不完全一致

证据：`opportunities.py:172` 使用六字母 FX 货币环；`managed_trading.py:379` 只接受 FOREX 计算模式 0/5。`weights.py:182` 将已知 DISABLED swap 当不可计价返回 None，导致具有零利息对冲腿的组合被整体排除。

修复：先明确支持的是外汇保证金合约、金属、指数还是其他 CFD。保留非 FOREX 拒绝保护，不可直接删除。按合约元数据、计价币种、盈亏/融资机制增加估值适配器；用 broker 盈亏计算结果校验自有模型，不用字符串拆币种模拟所有 CFD。已知融资为零应与未知/不支持区分；若 broker 另有管理费，需要单独纳入费用模型，不能由 swap disabled 推断全部持仓成本为零。

验收：明确支持/不支持品种清单；零 swap 腿允许参与经济评估；不支持估值的合约不进入自动交易。

## 3. 统一估值口径

### 3.1 所有决策最终使用账户币种

USD 可以继续作为展示/跨账户比较口径，但盈亏、手续费、保证金和风险门槛必须统一为账户币种，保留币种及转换快照。不得把非 USD 账户的 `position.profit` 直接标为美元。

### 3.2 入场前：按真实可下单手数评估持有情景

```text
Net(H, scenario)
  = Σ 每腿合约盈亏(方向, 取整手数, 入场可执行价, 情景退出可执行价)
  + Σ 在 H 之前符合资格的逐腿结算现金流
  − 入场及退出佣金/其他费用
  − 尚未反映在报价中的额外滑点与估值准备金
```

多单以 Ask 入、Bid 出；空单以 Bid 入、Ask 出。合约盈亏通过该品种明确支持的估值规则计算。**已经在入场/出场侧价中体现点差后，不再额外扣一遍 spread。** 若为解释目的按 mid 拆成本，入场半点差加出场半点差；在点差不变时是一份完整点差/腿的往返拖累，不是两份完整点差。

至少评估：价格基差不改善、温和不利偏移、退出点差扩大、正息腿减少/负息腿费用增大、错过下一结算。回均值的收益可单独显示为乐观/基准情景，不能成为确定性的成本抵扣。纯收息模式优先要求在选定保守情景和最长持有期内满足收益门槛，并独立通过压力损失预算；阈值是待配置政策，不宣称收益保证。

### 3.3 回本计算使用结算时刻

```text
payback_at = 最早使保守累计现金流和情景价格收益
             覆盖往返成本及缓冲的可行结算时刻
```

例如纯假设往返拖累 12 美元、每次合格结算净收 2 美元、其他变量不变，则至少需要 6 次这种结算；降到 1 美元则需要 12 次。未跨结算时点可能一分钱利息都没有，三倍息/不同腿倍率又会改变路径。不能据此显示固定“6 个自然日必回本”。限定窗口内无法覆盖时返回“不可回本/超出期限”，不得除以零、用负 carry 得到负天数或无限延长持仓。

### 3.4 持仓后：使用当前可兑现净盈亏

```text
NetLiquidation
  = 已实现价格盈亏
  + 剩余持仓按当前平仓侧价估算的未实现价格盈亏
  + 已结算融资与费用现金流（带正负号）
  + 经核对尚未进入前项的已累积融资
  − 尚未收取的平仓佣金及其他费用
  − 增量平仓滑点准备金
```

未来预计隔夜利息不计入当前可兑现收益。历史佣金按实际发生一次计入。若 broker profit 已含某项费用，则适配器必须标记包含范围，避免重复相加。报价仅是估值输入，并不保证全部腿同时按该价格成交；收益退出需要留执行缓冲，成交后用实际现金流核实结果。

## 4. 最小改造结构与接口草案

保留现有 Qt、worker、受管账本，不引入大型交易框架。

| 位置 | 建议职责与变更 |
|---|---|
| 新 `mt5_trader/economics.py` | 纯估值与决策：合约支持检查、账户币种成本、各持有情景、回本时刻、批次可兑现净盈亏、拒绝原因；不直接连接 MT5 |
| 新 `mt5_trader/rollover.py` | broker 时区、结算时点/资格、每日倍率、假日与逐腿融资情景；显式版本化 |
| `weights.py`、`spreads.py` | 实际可交易手数、精度与残余风险；保留价格观测和手数的明确区别；零/未知 swap 分离 |
| `opportunities.py` | 独立方向候选，成本精筛后排序，净息保持精度，不在成本评估前只保留最高净息 |
| `strategy.py` | 固定时间尺度信号；调用经济决策；开仓和已有仓位管理分开；退出按批次和原因 |
| `managed_trading.py` | 执行前重估、预算/期限检查、逐腿成交后再评估、持久化风险处置；扩展成交现金流与退出选择 |
| `worker.py` | broker 元数据/盈亏计算适配、时间戳一致的报价、独立持仓估值周期；与订单队列串行协调 |
| `database.py`、`services/db_service.py` | 新建版本化估值/日历/费用配置与成交现金流表，保持旧账本可读 |
| `ui/console.py` | 展示实际规模成本、下一次结算、保守回本区间、当前可兑现盈亏、状态/拒绝原因；取消隐式翻转 |

接口数据建议：

```text
BasketIntent:
  orientation_id, batch_id/request_id, actual_legs, account_currency
  quote_snapshot_id, valuation_version, policy_version, valid_until

EconomicsSnapshot:
  actual_lots, entry_liquidation_drag, estimated_roundtrip_cost
  carry_by_settlement, scenario_net_profit, payback_at
  net_liquidation, residual_exposure, stress_loss, margin_required
  cost_quality, input_timestamps, unsupported_reasons

Decision:
  action = wait | open | close_profit | reduce_risk | close_risk | blocked
  batch_ids, reason_codes, cost_budget, execution_deadline, policy_version
```

纯估值模块不读取 UI 控件，worker 的授权政策和最新 broker 数据为最终约束。UI 和 worker 可复用计算代码，但 worker 不信任 UI 提交的“已经盈利/已经通过”布尔值。原始报价和报价侧执行成本需保留用于复盘。

## 5. 实施顺序、迁移与完成条件

### 第一阶段：先纠正方向和经济数据契约

涉及 E01、E02、E07、E12。固定方向身份，删除隐式反向；修正多空净息说明；定义报价侧、账户币种和实际手数；完成方向扰动验证。没有完整经济估值的实盘新开仓应显示未具备准入能力，保留已有仓位对账和显式风险退出。此为建议实施行为，本轮尚未改动。

完成条件：每个信号可以解释“具体买卖哪些腿、预期哪种价格变化有利、该方向实际净息多少”；缺数据不会自动补零并发单。

### 第二阶段：成本模型、结算日历与经济准入

涉及 E03、E06、E09。新增纯估值模块，接入手续费/佣金规则、退出点差压力、利率变化情景、回本与绝对风险预算。机会筛选和手动/自动开仓复用同一规则。先做来源清楚的模型，不依据缺失历史伪造统计最优参数。

完成条件：每次入场有完整可追溯的现金成本、收益情景和拒绝/通过原因；成本不明或期限不达标不自动开仓。

### 第三阶段：收益账本、退出与持续持仓管理

涉及 E04、E05、E11。以事件表追加成交现金流；重建批次已实现和剩余收益；独立持仓管理周期；利润退出、风险退出和停止新增入场分开。

迁移：不重写既有订单归属记录。用确认的历史成交回填现金流；无法恢复开仓价格/费用/资金流水的批次标记经济估值不可用，保持归属安全及风险退出能力，不能填零并算成盈利。已有批次必须绑定显式政策版本，不自动套用未知默认止损值。

完成条件：重启/部分平仓/重复历史均不改变真实收益；UI 关闭不丢失已配置持仓管理；实际成交收益能与结单对账。

### 第四阶段：执行预算和真实历史验证

涉及 E08、E10。把截止时刻和成本上限传至执行边界，加入部分成交风险处置；统一时间尺度并记录双边行情、swap、费用版本。再在 Windows MT5 环境做完整验证。

完成条件：前置经济评估能够追踪到每腿实际成交偏差；过期机会不继续开首腿；部分成交有可解释的对冲/撤回方案；历史收益估计不会把当前点差灌入过去。

## 6. 待配置的业务输入与验证边界

实施前应从 broker 规则/实际结单确认，而不是凭代码猜测：支持品种和账户币种；佣金单双边及最低收费；swap 单位、每周倍率、结算时区和资格；节假日规则；额外持仓/管理费；各合约盈亏和结算机制。策略参数包括最长持有期、最大允许亏损、入场成本上限、目标净利润、滑点预算、残余敞口与压力限额。初始值应显式配置，不称为“最优参数”。

建议编写但本轮未执行的测试：方向与反向 swap、0.01 手及取整边界、宽点差/手续费超预算、两种账户币种、无结算/三倍息/不同腿倍率、净息骤变、Z 回归但亏损/未回归但盈利、批次分层/部分平仓、费用重复/延迟入账、未知成本、新鲜度与队列超时、部分成交补救、UI 生命周期与重启恢复、非 FOREX 拒绝、零 swap 对冲腿。

静态审查能够证明当前代码缺哪些条件和方向映射存在反例，不能证明具体 broker 的费用金额、短期盈利概率或真实成交质量。Windows 验证及历史/模拟交易数据校准仍是后续事项。
