## 时间修复为何不用自动校准

单凭 `server_ts - local_ts`，无法区分“broker 写入了本地墙钟时间”与“报价已经陈旧”。原建议 `round(delta/900)*900` 能把整 30 分钟旧行情当成时区偏移，残差恰好为零，从而绕过新鲜度检查。这个反例在逻辑上成立，不需要运行探针。

MT5 官方 `copy_rates_from` 文档和示例采用 UTC（https://www.mql5.com/en/docs/python_metatrader5/mt5copyratesfrom_py）。论坛中的特定 broker 现象不能据此推广为所有 MT5 API 都需要减去服务器时区。本轮采用显式契约：

- 默认 `UTC`，标准 MT5 epoch 原值不变。
- 确认目标 broker 的历史和 tick 都把服务器墙钟编码为 epoch 后，才设置 `UTC+03:00` 等固定偏移，或核实正确的 IANA 时区。
- 固定偏移不自动随夏令时变化；IANA 时区按报价对应日期转换。重复/缺失的 DST 墙钟时间不能唯一还原，实时报价拒绝、历史该 bar 跳过，保留缺口，不猜 fold。
- `clock_ready` 表示显式时间基准可用，不代表该报价新鲜。任何交易仍须通过身份、连接、报价年龄、读取时间与执行前重核验。
- 账户新增 `broker_timezone` 与 `quote_max_age` 配置；旧库下次启动以默认 UTC/60 秒扩展字段。本轮没有打开或修改用户实际数据库。
- Windows 常无系统 IANA 数据，因此声明 `tzdata` 依赖并纳入 PyInstaller 数据；本地没有安装它。
- 错误配置仍可能产生错误换算，软件不能自行证明用户填写的偏移；必须用目标账户数据核实，尤其不要只因 MT5 终端图表显示服务器时间就修改 API 基准。

## 分钟统计契约

窗口单位是自然分钟。统计仅包含 `[当前分钟-window, 当前分钟)` 范围内已收盘的 M1，休市或缺口不补造样本。实时帧更新当前分钟候选收盘值；相同分钟收到 1 次或 300 次不会增加样本数。窗口内有 n 个有效分钟时，H1 先验的混合权重逐渐降至零，避免“第 10 个 tick”突然切换；标准差至少为 H1 先验的 10%（并有数值下限）。历史请求返回时保留其最新 bar 之后和同分钟的实时更新。

图表仍采用当前 pyqtgraph 与原界面布局。本轮修正数据时钟和统计口径，保留此前屏幕时间分桶的峰谷绘制方案。没有把换库当成数据错误的修复办法，也没有宣称已通过长期图形性能测试。
